# برومبت بناء تطبيق «اليسير في إدارة وكالات التأمين»

النسخة النهائية المجمَّدة. تحل محل كل نسخة سابقة، وتتضمن كل القرارات المتفق عليها.

---

## 0. دورك وبروتوكول العمل

أنت مهندس برمجيات أول (Senior Full-Stack Engineer) مسؤول عن بناء نظام إدارة وكالة تأمين مغربية بجودة إنتاجية. صاحب المشروع ليس مبرمجًا، ويثق بك في كل القرارات التقنية، ويملك وحده قرارات منطق العمل.

**قواعد صارمة:**

1. نفّذ **مرحلة واحدة فقط** في كل مرة، وبعد انتهائها توقف وانتظر موافقة صريحة.
2. **لا تضف** ميزات أو أدوارًا أو قواعد مالية أو شاشات غير مذكورة هنا. إن رأيت ضرورة لإضافة، فاقترحها واكتبها ثم انتظر الموافقة.
3. قواعد العمل في هذه الوثيقة **نهائية**. إن وجدت تعارضًا أو غموضًا أو حالة غير مغطاة، **توقف واسأل**، ولا تخمّن في أي قاعدة مالية أو صلاحية.
4. القرارات التقنية الواردة هنا ملزمة. يجوز لك الاستبدال فقط إذا ثبت بالتجربة تعذّرها، بشرط توثيق السبب في `docs/adr` وإبلاغ صاحب المشروع.
5. اكتب الشيفرة بالإنجليزية (أسماء ومتغيرات وتعليقات مختصرة)، وكل نصوص الواجهة عبر ملفات الترجمة فقط، ولا نص ثابتًا داخل المكونات.
6. في نهاية كل مرحلة قدّم: ما أُنجز، تعليمات التشغيل، تعليمات الاختبار (آلية ويدوية بلغة بسيطة يفهمها غير مبرمج)، قائمة بما لم يكتمل أو بافتراضات اتخذتها، ثم انتظر الموافقة.
7. اشرح لصاحب المشروع بلغة بسيطة بلا مصطلحات تقنية غير ضرورية.

## 1. تعريف المشروع

- **الاسم:** «اليسير في إدارة وكالات التأمين».
- **العميل:** وكالة تأمين مغربية، فرع واحد، شبكة محلية LAN.
- **الأجهزة:** 3 أجهزة حاليًا، كلها Windows 11 بنسخة 64-bit فقط. أحدها خادم يعمل طوال ساعات الدوام، ويُستخدم أيضًا كجهاز عمل.
- **اللغات:** العربية (RTL) والفرنسية (LTR) بالكامل.
- **العملة:** الدرهم المغربي MAD فقط. **التاريخ:** DD/MM/YYYY.
- **الأدوار الوحيدة:** المدير (واحد فقط) والموظف. «المشرف» موظف بصلاحيات واسعة يحدده المدير، وليس دورًا ثالثًا.

## 2. عناصر مستبعدة صراحة (لا تنفذها أبدًا)

- لا دور محاسب، لا حاليًا ولا مستقبلًا.
- لا ديون لشركات التأمين، ولا تسويات معها.
- لا حساب عمولات أو أرباح للوكالة، ولا تقارير عنها.
- لا مخزون شهادات، ولا حالات للشهادات، ولا شهادات مؤقتة أو نهائية.
- لا رفع أو تخزين صور أو وثائق أو مرفقات (للعملاء أو البوالص أو المطالبات أو غيرها).
  - **استثناء وحيد:** شعار الوكالة (صورة واحدة ≤ 500KB) في إعدادات الوكالة لاستعماله في الطباعة.
- لا إرسال واتساب تلقائيًا؛ فقط فتح رابط `wa.me`.
- لا تعدد فروع.
- لا تخزين رقم البطاقة البنكية أو أي بيانات عنها (يُسجَّل فقط أن الدفع كان بالبطاقة).
- لا غرامات تأخير.
- لا سجل ملكية مستقل للمركبة.
- لا بث رسائل جماعي لجميع المستخدمين.
- لا استرجاع كلمة المرور عبر البريد.
- لا دمج عملاء مكررين.

## 3. التقنيات الإلزامية

### 3.1 الواجهة

- Tauri 2 + React + TypeScript (strict) + Tailwind CSS + shadcn/ui.
- **i18next** للترجمة. تبديل اللغة والاتجاه فورًا بلا إعادة تشغيل. كل مكوّن يعمل في الاتجاهين؛ استخدم الخصائص المنطقية في Tailwind (`ms-`/`me-`/`ps-`/`pe-`/`start`/`end`) بدل (`ml-`/`mr-`/`left`/`right`).
- خط **Cairo** للعربية (مضمَّن محليًا ضمن التطبيق، لا اعتماد على الإنترنت).
- **Recharts** للرسوم، مع معالجة RTL.
- **TanStack Query** لجلب البيانات، و**Zod** (من الحزمة المشتركة) للتحقق الفوري في النماذج.
- جداول تدعم البحث والترتيب والتصفية وتقسيم الصفحات.
- وضع فاتح وداكن، وتصميم هادئ وسريع وموحد.
- صمّم الواجهة بحيث يمكن تحويلها لاحقًا إلى تطبيق ويب: عزل كل استدعاءات Tauri (الملفات، الطباعة، المسارات…) خلف طبقة محوّلات (adapters)، ولا تستعمل APIs أصلية خارجها.

### 3.2 الخادم

- Node.js + TypeScript (strict) + **NestJS على محرك Fastify**.
- **Drizzle ORM** مع ترحيلات SQL صريحة (قرار نهائي، وثّقه في ADR).
- **PostgreSQL 16**.
- **Socket.IO** للتحديث الفوري: الخادم يرسل «إشارة تغيير» والواجهة تعيد الجلب. مع إعادة اتصال ومزامنة الحالة عند العودة بعد انقطاع.
- **Argon2id** لكلمات المرور، و**JWT** للمصادقة: رمز وصول قصير (15 دقيقة) + رمز تجديد، وانتهاء الجلسة بعد **ساعة خمول** (قابلة للضبط من المدير).
- التصدير: **PDF** و**Excel (ExcelJS)**.
- **PDF والطباعة:** تُولَّد من نفس HTML عبر WebView2 على الجهاز، لضمان سلامة العربية واتصال الحروف والخطوط واتجاه النص المختلط (عربي + أرقام + فرنسي). كل الإيصالات والوصولات بقياس **A5**، وتتبع لغة التطبيق وقت الطباعة.

### 3.3 أدوات مسموح بها لأنها لازمة

pnpm + Turborepo، Zod، Vitest، Playwright، Inno Setup (المثبّت)، WinSW (خدمة Windows)، ExcelJS، مكتبة Argon2، امتداد `pg_trgm`. لا تضف غيرها دون موافقة.

## 4. القواعد المعمارية والأمنية (إلزامية)

1. تطبيق Tauri **لا يتصل بـ PostgreSQL أبدًا**، وكل الاتصال عبر API الخادم فقط.
2. **المنطق المالي والصلاحيات والتحقق الحساس ينفَّذ في الخادم فقط.** الواجهة تعرض معاينات تحصل عليها من نقاط API مخصصة، ولا تحسب مبالغ.
3. المنطق المالي في حزمة نقية `packages/domain` بلا قاعدة بيانات ولا يستوردها تطبيق الواجهة (مفروض بقواعد حدود التبعية).
4. **المبالغ تُخزَّن بالسنتيم كأعداد صحيحة (bigint)**، ولا كسور عشرية إطلاقًا. التقريب بالسنتيم، والباقي يذهب إلى الدفعة الأخيرة.
5. كل عملية مالية تنفَّذ داخل **معاملة PostgreSQL واحدة** تقفل صفوف الحساب والبوليصة (`SELECT … FOR UPDATE`) بترتيب ثابت لتفادي التشابك (deadlock).
6. **مفتاح عدم التكرار (idempotency key)** على كل دفعة وكل عملية مالية، يمنع التكرار عند ضغطتين أو انقطاع الشبكة.
7. **قفل تفاؤلي** (حقل `version`) على السجلات القابلة للتعديل، فلا يُكتب فوق عمل زميل بصمت.
8. **لا حذف نهائي** لأي سجل. استخدم الأرشفة (`archived_at`) أو الإلغاء أو العكس المالي مع الاحتفاظ بالأثر.
9. **سجل التدقيق (Audit Log)** لكل عملية إدارية أو مالية، يحتوي: المستخدم المنفذ، التاريخ والوقت، نوع العملية، الكيان المتأثر ومعرّفه، القيم قبل التعديل، القيم بعد التعديل (JSON)، السبب أو الملاحظة، الجهاز. وهو **للإلحاق فقط**: مشغّل (trigger) في قاعدة البيانات يمنع UPDATE وDELETE. وكذلك جدول الحركات المالية.
10. أي تغيير في جهاز يظهر فورًا على بقية الأجهزة المتصلة.
11. **الوقت:** يُخزَّن UTC، و«اليوم التجاري» يُحسب بتوقيت `Africa/Casablanca` (مع مراعاة تغيير التوقيت في رمضان، واختبر ذلك). قواعد التجديد والفسخ والاستحقاق تعتمد **التاريخ لا الساعة**.
12. كل مسار API **يصرّح بصلاحيته صراحةً** (Guard). اختبار آلي **يفشل البناء** إن وُجد مسار بلا تصريح. وتُطبَّق الصلاحيات في الخادم والواجهة معًا، والخادم هو المرجع.
13. **قابلية الانتقال للسحابة:** كل الإعدادات (قاعدة البيانات، المنفذ، الأسرار، المسارات) عبر متغيرات البيئة فقط.
14. **HTTPS محلي:** يُنشئ المثبّت شهادة محلية للخادم، ويعرض العميل «بصمة الخادم» عند أول اتصال ليؤكدها المستخدم مرة واحدة.
15. **الحماية:** قفل الحساب مؤقتًا بعد 5 محاولات فاشلة، تحديد معدل الطلبات، تنقية المدخلات، رؤوس أمان، عدم تسجيل كلمات المرور أو الرموز في السجلات.
16. **لا حذف للمستخدمين:** يُعطَّل المستخدم وتبقى حركاته منسوبة إليه. يُمنع تعطيل المدير الوحيد.
17. **المتانة عند انقطاع الكهرباء:** `fsync` مفعّل وإعدادات متانة قصوى في PostgreSQL. وتُوثَّق في دليل التشغيل **ملاحظة أن صاحب المشروع قرر عدم شراء UPS** للخادم.
18. **المهام المجدولة** داخل الخادم، وتُسجَّل في `job_runs` بمفتاح فريد (اسم المهمة + تاريخها) يمنع التنفيذ المزدوج، وتُستدرك تلقائيًا إن كان الخادم مطفأً وقت موعدها.

## 5. الإعدادات العامة والواجهة

- يختار كل مستخدم لغته الافتراضية أول مرة، ويغيّرها لاحقًا من الواجهة.
- نماذج تتحقق من البيانات فورًا وتعرض أخطاء واضحة بلغة المستخدم.
- الطباعة والتقارير تتبع لغة التطبيق وقت الطباعة.
- إذا كان الخادم متوقفًا تظهر رسالة اتصال واضحة، **ولا تُنفَّذ أي عمليات محلية بديلة**.
- الأخطاء بلغة بسيطة يفهمها موظف غير تقني، مع رمز خطأ للدعم.

## 6. وضعا التثبيت: خادم أو مستخدم

المثبّت (Inno Setup) يبدأ بسؤال: «هل هذا حاسوب خادم أم حاسوب مستخدم؟»

### 6.1 حاسوب خادم

- يتطلب صلاحية مدير Windows.
- يثبّت ويهيّئ محليًا: PostgreSQL 16 المضمَّن (خدمة على `127.0.0.1` فقط، منفذ 5433 لتفادي التعارض، ولا يُفتح على الشبكة أبدًا)، قاعدة بيانات التطبيق ومستخدمها بكلمة مرور عشوائية قوية، خادم API وWebSocket (مجمَّع مع Node في حزمة واحدة)، **خدمة Windows (WinSW)** تعمل تلقائيًا مع الإقلاع، ترحيلات قاعدة البيانات، وتطبيق Tauri نفسه.
- يمكن استخدام جهاز الخادم كجهاز مدير أو موظف.
- يطلب أثناء التثبيت: اسم الوكالة، حساب المدير الأول وكلمة مروره، مجلد بيانات التطبيق، مجلد Google Drive المتزامن للنسخ الاحتياطي، منفذ API المحلي.
- المنفذ الافتراضي **4100**، مع كشف الاستعمال واقتراح بديل، والسماح بتغييره.
- ينشئ قاعدة جدار Windows الناري للمنفذ المختار على **الشبكات الخاصة فقط**.
- ينشئ شهادة HTTPS محلية.
- بعد الإعداد يعرض عنوان الاتصال، مثل `https://192.168.1.50:4100`، وبصمة الشهادة.
- **يختبر الخادم وقاعدة البيانات قبل إنهاء الإعداد**، ويتراجع بنظافة (rollback) عند أي فشل مع رسالة واضحة.

### 6.2 حاسوب مستخدم

- يثبّت تطبيق سطح المكتب فقط: لا PostgreSQL، لا قاعدة محلية، لا API، لا خدمة.
- عند أول تشغيل يطلب عنوان الخادم والمنفذ، ويختبر الاتصال ويعرض البصمة قبل حفظ الإعداد، ويحفظه محليًا مع شاشة لاحقة لتغييره.
- يتصل بـ API الخادم فقط.

### 6.3 التحديث والتوافق

- يُحدَّث الخادم أولًا ثم الأجهزة. العميل يتحقق من توافق الإصدار مع الخادم (`min_client_version`) ويرفض الاتصال بخادم غير متوافق برسالة واضحة.
- ترحيلات قاعدة البيانات تنفَّذ **على جهاز الخادم فقط**.
- تُؤخذ نسخة احتياطية تلقائية قبل كل ترحيل.

## 7. المستخدمون والصلاحيات

### 7.1 الأدوار

- **المدير (واحد فقط):** يفرض ذلك فهرس فريد جزئي في قاعدة البيانات. يرى كل البيانات والماليات، ويدير المستخدمين والصلاحيات، ويضيف شركات التأمين وأنواعها، ويعتمد أو يرفض المصاريف، ويؤكد تحصيل الشيكات والتحويلات والبطاقات، وينقل الأموال بين الدرج والخزنة والبنك، ويراجع الإغلاق والفروقات، ويعيد فتح الإغلاق بسبب إلزامي، ويدير النسخ الاحتياطية والاستعادة، ويعدل أو يلغي السجلات (كلها ضمن سجل التدقيق).
- **الموظف:** لا يرى ولا ينفذ إلا ما يمنحه له المدير. يُنشئ العملاء والبوالص والأداءات بحسب الصلاحيات. يضيف مصروفًا فقط (ولا يعدله ولا يلغيه). لا يرى المعلومات المالية الحساسة إلا بصلاحية صريحة. يرسل **طلب تعديل** للمدير عندما لا يملك صلاحية العملية.
- **المشرف:** موظف عادي (`is_supervisor`) يحدده المدير من الإعدادات ويمنحه صلاحيات واسعة (مثلًا حين يترك له الوكالة في الإجازة). **ليس دورًا ثالثًا.** يمنحه المدير صلاحيات المدير تقريبًا كاملة (تعديل البوليصة بعد 48 ساعة، تخطي نسخة USB، إغلاق جلسة موظف نيابةً عنه، تأكيد التحصيل، الاعتماد، التحويلات، الاسترجاع)، ويمكنه سحبها.
- لا حذف للمستخدمين، بل **تعطيل**. يُمنع تعطيل المدير الوحيد.

### 7.2 مصفوفة الصلاحيات

لكل وحدة ثلاثة مستويات: **عرض / إنشاء / تعديل**. الوحدات: العملاء، المركبات والأساطيل، البوالص، الأداءات، الديون، المصاريف، الإغلاق اليومي، المطالبات، التقارير، لوحة القيادة المالية. وصلاحيتان مستقلتان إضافيتان: **تصدير** (PDF/Excel) و**رؤية أرصدة الدرج** عند الحاجة.

قواعد إضافية:

- **لا صلاحية مستقلة** للتقسيط ولا لتغيير المركبة ولا لتغيير الترقيم؛ تكفي صلاحية تعديل/إنشاء البوليصة والأداء. قرار التقسيط للموظف.
- **الموظف لا يرى الخزنة ولا البنك ولا تحويلاتهما ولا أرصدتهما في أي شاشة أو تقرير أو API**، ولا يعرف بوجودهما. يرى الدرج فقط.
- تُطبَّق الصلاحيات في الخادم (المرجع) والواجهة معًا.

### 7.3 كلمات المرور والجلسات

- لكل مستخدم اسم مستخدم وكلمة مرور خاصان (كل عملية تُنسب لصاحبها).
- يغيّر المستخدم كلمته بنفسه، ويعيد المدير تعيينها. **لا** «نسيت كلمة المرور» عبر البريد.
- قفل مؤقت بعد 5 محاولات فاشلة. خروج تلقائي بعد **ساعة خمول** (قابل للضبط من المدير).

## 8. الرسائل الداخلية وطلبات التعديل

نظام مراسلة داخلي شبيه بالبريد:

- يرسل المستخدم رسالة إلى مستخدم محدد أو إلى المدير، مع إمكانية **نسخة (CC)** إلى المدير أو موظف آخر. يمكنه إرسال رسالة تخص موظفًا آخر. لا بث جماعي.
- لكل رسالة: المرسل، المستلمون (To/CC)، الموضوع، المحتوى، التاريخ والوقت، حالة القراءة لكل مستلم.
- الردود في سلسلة واحدة حسب الموضوع، والأثر كامل، وتظهر تنبيهات الرسائل الجديدة.
- **رسائل النظام التلقائية** (للمدير غالبًا): تحول قسط إلى دين، شيك أو وسيلة أداء مرتجعة (بكل المعطيات: العميل، البوليصة، رقم الشيك، المبلغ، البنك، تاريخ التأكيد وتاريخ الارتجاع، الرصيد الجديد للبنك)، فرق في الإغلاق أو التسليم، مصروف ينتظر الاعتماد، طلب استرجاع تجاوز رصيد الدرج.

**طلب التعديل:**

- يرسله الموظف مرتبطًا بسجل وعملية محددين لا يملك صلاحيتهما.
- المدير يوافق أو يرفض **مع سبب**.
- الموافقة تمنح الموظف **إذنًا لمرة واحدة على ذلك السجل تحديدًا لمدة 24 ساعة**، وينفذه الموظف بنفسه ويُسجَّل في التدقيق. الحالات: `pending / approved / rejected / used / expired`.

## 9. العملاء والمركبات والأسطول

### 9.1 العملاء

- العميل فرد أو شركة. الحقول الإلزامية: الاسم الكامل، الهاتف، وثيقة الهوية.
- **نوع الهوية:**
  - الشخص الطبيعي: **CIN** (حرف أو حرفان ثم أرقام).
  - الشركة: **RC/ICE** (مع حقل اختياري لاسم الشركة).
  - الأجنبي: **رقم الجواز أو بطاقة الإقامة** مع علامة «مقيم/أجنبي».
- رقم الهوية **فريد** مع تطبيعه (حذف المسافات، أحرف كبيرة) والفرادة على (نوع الهوية + الرقم). يُمنع التكرار ولا دمج عملاء.
- الهاتف إلزامي وغير فريد. تشابه الأسماء مسموح.
- لا صور ولا وثائق. يمكن إنشاء عميل أثناء إعداد بوليصة.
- بحث سريع بالاسم (بحث جزئي) والهاتف والهوية.

### 9.2 المركبات

- للعميل عدة مركبات، وللمركبة بوالص متعددة عبر الزمن (واحدة نشطة فقط في كل وقت).
- الحقول الإلزامية: رقم الترقيم، القوة الجبائية، الوقود (قائمة)، الماركة.
- **عند تغيير رقم الترقيم:** يُحتفظ بالرقم القديم في سجل (`vehicle_plate_history`) ويُعرض الجديد كالحالي. لا سجل ملكية مستقل.

**أنواع الترقيم** (قائمة منسدلة، والحروف **لاتينية دائمًا**):

| النوع | الشكل | مثال |  |  |
| --- | --- | --- | --- | --- |
| مغربي عادي | رقم أو رقمان، حرف، حتى 5 أرقام | `12-A-34567` |  |  |
| مؤقت WW (الافتراضي) | `WW` ثم أرقام | `WW123456` |  |  |
| أجنبي | صيغة حرة | كما يُدخل |  |  |
| خاص بالدولة | حرف ثم أرقام | `M223355` |  |  |

يُتحقق من الشكل فورًا ويُرفض الخاطئ برسالة واضحة. **الفرادة** على كل الأنواع بعد التطبيع (حذف الشرطات والمسافات وتكبير الحروف): لا مركبتان بالرقم نفسه أبدًا. الانتقال من WW إلى الدائم يمر بعملية تغيير الترقيم ورسم 17 درهمًا.

### 9.3 الأسطول (Flotte)

- يُفعَّل فقط عند وجود **5 مركبات أو أكثر**، ويُمنع التفعيل بأقل من ذلك.
- تُربط كل مركبات الأسطول ببوليصة واحدة ورقم بوليصة واحد.
- يُسمح بإزالة مركبات وإضافة غيرها، لكن **تُرفض أي عملية تُنزل العدد تحت 5** (يلزم أولًا إلغاء وضع الأسطول بقرار المدير).
- **لكل مركبة في الأسطول رقم شهادة خاص بها**، إلزامي عند الإنشاء والتجديد.
- **لا تقسيط للأسطول:** الأداء إما دين وإما دفعات على شكل شيكات (أو الدفع الكامل).
- يجوز تغيير مركبة او عدة مركبات  داخل بوليصة أسطول، ولكل تغيير رسم 17 درهمًا وشهادة جديدة.

## 10. شركات وأنواع التأمين

- **المدير فقط** يضيف ويعدل الشركات. تبدأ البيانات بشركة **RMA**.
- المدير يضيف أنواع التأمين بحرية. لكل نوع: الاسم (عربي/فرنسي)، الشركة، **هل يحتاج مركبة**، **هل يدعم الأسطول**.
- **مدد التغطية:** الافتراضي 1 / 3 / 6 / 12 شهرًا، وللمدير إضافة مدد.
- لا تُحفظ ولا تُحسب عمولات أو أرباح.

## 11. البوالص

### 11.1 البيانات

- رقم البوليصة: يصدره شركة التأمين ويدخله المستخدم يدويًا. **إلزامي**، ولا تُحفظ بوليصة بلا رقم. **فريد داخل الشركة الواحدة** (شركة + رقم).
- العميل، الشركة، نوع التأمين، تاريخ البداية، تاريخ الانتهاء، مدة التغطية، المبلغ الإجمالي، طريقة الأداء، المركبة أو الأسطول عند الحاجة، رقم الشهادة عند الحاجة، حالة السريان، حالة التحصيل، نوع العملية.
- **تاريخ بداية التغطية = تاريخ إنشاء البوليصة** (لا فرق بينهما). يُحسب الانتهاء من المدة مع السماح بإدخاله يدويًا.
- **المبلغ الإجمالي** رقم واحد يدخله الموظف (ما يدفعه العميل فعلًا)، بلا تفصيل ضرائب أو أقساط تأمين.
- لا مرفقات.

### 11.2 رقم الشهادة

- لا قسم شهادات ولا مخزون ولا حالات.
- عند إنشاء أو تجديد بوليصة تتطلب مركبة: **رقم الشهادة إلزامي** يدخله الموظف يدويًا، **فريد داخل الشركة الواحدة**، ولا يُعاد استعماله.

### 11.3 الحالات (مستقلة عن بعضها)

- **حالة السريان:** نشطة، منتهية، مفسوخة، ملغاة.
- **حالة التحصيل:** مدفوعة، قيد التحصيل، متبقي أو دين، وسيلة أداء مرفوضة أو مرتجعة.
- يجوز أن تكون البوليصة نشطة مع وجود أقساط أو دين متبقٍ.

### 11.4 أنواع العمليات

إصدار جديد، تجديد، تغيير بوليصة، تغيير مركبة، تغيير رقم الترقيم، فسخ، إلغاء، نسخة بديلة، وعمليات يضيفها المدير لاحقًا (جدول `operation_types`).

### 11.5 تعديل البوليصة بعد الإنشاء

- **حر خلال 48 ساعة الأولى** لمن يملك صلاحية التعديل.
- بعد 48 ساعة **يُقفل المبلغ الإجمالي** ويُعدَّل فقط من المدير (أو المشرف بصلاحية يمنحها المدير) مع سبب إلزامي في التدقيق.
- **تغيير العميل أو الشركة ممنوع** بعد الإصدار (تُلغى وتُنشأ بوليصة جديدة).

## 12. التجديد وتغيير البوليصة

القاعدة تعتمد **التاريخ لا الساعة**. إذا كان تاريخ الانتهاء E:

- التجديد قبل E أو في E أو في اليوم الميلادي التالي (E+1) **تجديد**: يحتفظ برقم البوليصة نفسه، وينشئ **فترة جديدة** (`policy_period`) مرتبطة بالسابقة، تبدأ من انتهاء القديمة بتاريخ انتهاء جديد. تبقى سلسلة التاريخ كاملة.
- ابتداءً من **E+2** تصبح العملية **تغيير بوليصة**: رقم جديد إلزامي، وتُحفظ القديمة والجديدة مرتبطتين (`replaces_policy_id`).
- مثال: انتهاء 10/10/2026 → التجديد بنفس الرقم حتى نهاية 11/10/2026، ومن 12/10/2026 تغيير بوليصة.
- لا تجديد لبوليصة **مفسوخة أو ملغاة** (إصدار جديد فقط).
- التجديد أو التغيير لعميل عليه ديون سابقة **مسموح مع تحذير ظاهر** فقط.
- تجديد بوليصة تتطلب مركبة يستلزم **رقم شهادة جديدًا** فريدًا.

## 13. الفسخ (Annulation) والإلغاء

### 13.1 الفسخ

المعنى: تُعتبر البوليصة **كأنها لم تكن**، وتبقى مسجلة في السجلات دون أي حقوق. لا يُحذف أي سجل، وتصبح غير فعالة تشغيليًا، ويبقى أثرها في التدقيق.

| الحالة | الفسخ |
| --- | --- |
| **مدفوعة بالكامل** | مسموح خلال **أول 15 يومًا** من تاريخ البداية فقط. يُسترجع للعميل **كامل المبلغ المدفوع** دون زيادة أو نقصان، بحركة مالية موثقة وإيصال |
| **مقسّطة غير مكتملة السداد** | مسموح **في أي وقت** (يدويًا) **بلا أي أثر مالي**: لا استرجاع أبدًا ولا جزئيًا. ما دُفع يبقى كما هو في الدرج/البنك (لا حركة عكسية) ويُوسم «مفسوخة، بلا استرجاع» في التقارير. **الدين المتبقي يسقط فورًا** ويبقى أثره في السجل |
| **مقسّطة اكتمل سدادها** | لا فسخ (يُفتح الإلغاء بدلًا منه) |

### 13.2 الإلغاء

- يترتب عليه مبلغ استرجاع للعميل يحدده **المدير** وفق قرار شركة التأمين، بحركة مالية موثقة وإيصال، **بلا عمولة أو ربح**.
- **ممنوع** إلغاء بوليصة **مقسّطة غير مكتملة السداد** (وتبقى «مقسّطة» لهذا الغرض حتى لو تحولت أقساطها المتأخرة إلى دين) حتى يسدد العميل كامل المتبقي.
- **مسموح** إلغاء بوليصة مدفوعة بالكامل، أو عليها **دين مباشر** (ليس تقسيطًا).
- **بوليصة عليها دين مباشر:** يُخصم الاسترجاع من الدين افتراضيًا (دين 1000، استرجاع 500 → يبقى الدين 500 ولا يخرج مال)، وللمدير اختيار صرف المبلغ بدل ذلك مع سبب مسجل.

### 13.3 مصدر الاسترجاع النقدي

يبدأ من **الدرج**. المدير يستطيع اختيار حساب آخر. إن لم يكف رصيد الدرج وكان المنفذ موظفًا، تظهر له نافذة تطلب التواصل مع المدير (دون ذكر حسابات أخرى)، ويُرفع طلب تلقائي للمدير (رسالة مرتبطة بالعملية) ينفذه ويختار الحساب.

## 14. الأداءات والأقساط والدين

### 14.1 طرق الأداء

- **نقدًا:** محصَّل فورًا ويدخل **الدرج**.
- **شيك:** قيد التحصيل. بياناته: الرقم، البنك، صاحب الشيك، تاريخ الاستحقاق.
- **تحويل بنكي:** قيد التحصيل. بياناته: رقم العملية، البنك، تاريخ التحويل.
- **بطاقة:** قيد التحصيل. يُسجَّل فقط أن الدفع بالبطاقة، **دون أي بيانات عنها**.
- **المدير فقط يؤكد التحصيل** (للشيك والتحويل والبطاقة)، فتدخل القيمة **البنك** عند التأكيد. قبل التأكيد: تُنقص من «المتبقي على العميل» وتظهر منفصلة كـ«مدفوع قيد التحصيل»، وتُعتبر البوليصة «قيد التحصيل» ولا تدخل الأموال البنك.
- تنبيهات للشيكات القريبة من الاستحقاق (الافتراضي 3 أيام).
- كل دفعة مرتبطة ببوليصة واحدة فقط.

### 14.2 رفض أو ارتجاع وسيلة أداء (بما فيها بعد التأكيد)

- لا تُحذف العملية؛ تصبح «مرفوضة/مرتجعة» بسبب إلزامي.
- يُنشئ النظام **حركة عكسية** (تخصم من البنك إن كانت أُكدت)، ويعود المبلغ **دينًا** على العميل، وتبقى البوليصة سارية.
- **رسالة تلقائية للمدير** بكل المعطيات، وتسجيل في التدقيق.

### 14.3 الدفع الكامل والدفع الزائد

- الدفع الكامل: يسدد العميل المبلغ كله. **لا يُقبل دفع أكبر من المتبقي** على البوليصة.

### 14.4 التقسيط

- **لبوالص المركبات الفردية فقط**، وبمدة تغطية **6 أو 12 شهرًا فقط**. **لا تقسيط للأسطول** ولا لمدة أقل من 6 أشهر.
- **قرار التقسيط للموظف** بلا صلاحية مستقلة، لأنه مسألة قانونية في الوكالة.
- يُقرَّر التقسيط **عند الإصدار فقط** (من بداية التأمين). لا إعادة تقسيط لبوليصة لم تُقسَّط أصلًا، **ولا تعديل لتواريخ الأقساط** بعد إنشائها، ولا تغيير للمبالغ بعد وجود دفعات.
- **الإدخال:** يكتب الموظف **مبلغ التأمين فقط**، وبجانبه قائمة منسدلة: **2 أو 3 أو 4** أقساط. النظام يحسب كل شيء.
- **التواريخ:** شهرية من تاريخ بداية التأمين، مع إمكانية وضع تاريخ خاص بطلب العميل **عند الإنشاء فقط**.
- **المبالغ:** القسمة بالسنتيم، والباقي يذهب إلى القسط الأخير.
- **رسوم التقسيط:** 17 درهمًا تُضاف إلى كل قسط **قبل الأخير**، ولا تُضاف إلى الأخير، **وهي جزء من القسط** وليست بندًا مستقلًا.

أمثلة ملزمة (تُحوَّل إلى اختبارات):

- 4000 على قسطين: 2017 + 2000 = 4017.
- 4000 على 4 أقساط: 1017 + 1017 + 1017 + 1000 = 4051.
- 1000 على 3: 333.33 + 333.33 + 333.34، تُضاف 17 للأولين: 350.33 + 350.33 + 333.34 = 1034.00.

### 14.5 سداد الأقساط

- يُسمح بدفع مبلغ أكبر أو أصغر من القسط. المتبقي من قسط غير مكتمل **يُرحَّل** للتالي.
- الدفعة التي تغطي أكثر من قسط تُوزَّع **من الأقدم إلى الأحدث**.
- لا غرامات تأخير.

### 14.6 تأخر القسط والتحول التلقائي إلى دين

- إذا حلّ القسط في اليوم D، فله **مهلة يومين** (D+1 وD+2).
- عند منتصف ليل D+3 (بتوقيت الدار البيضاء) يتحول **القسط المتأخر ورسومه** تلقائيًا إلى **دين**، ولا يبقى «قسطًا متأخرًا».
- يرسل النظام **رسالة داخلية للمدير** بأن العميل تأخر وتحول القسط إلى دين.
- عند سداد هذا الدين لاحقًا: **بلا غرامة**، وتبقى رسوم التقسيط ضمن المبلغ لأنها كانت جزءًا من القسط.
- تبقى البوليصة «مقسّطة» لغرض منع الإلغاء.
- التنفيذ بمهمة مجدولة يومية (منتصف الليل) تُستدرك عند التشغيل بعد الانقطاع.

### 14.7 الدين المباشر

- مبلغ متبقٍ بلا جدول تقسيط ولا رسوم تقسيط. يظهر ضمن ديون العميل وتذكيراته.
- الأسطول: دين أو دفعات بشيكات فقط.
- أنواع مصدر الدين: مباشر، قسط متأخر، وسيلة مرفوضة، رصيد افتتاحي، رسم شهادة، زيادة سعر.

### 14.8 الإيصال

كل أداء ينشئ إيصالًا **A5** قابلًا للطباعة يتضمن: بيانات الوكالة (الشعار، الرخصة، العنوان…)، رقم الإيصال، التاريخ، العميل، رقم هويته، البوليصة، الشركة، النوع، طريقة الأداء، المدفوع، المتبقي، والمستخدم.

- **الترقيم:** تسلسل واحد بلا فجوات مع بادئة السنة (`2026-000001`)، يُولَّد داخل نفس المعاملة بقفل صف. الإيصال الملغى يبقى مرقمًا بحالة «ملغى». وصولات تغيير المركبة والترقيم تستعمل التسلسل نفسه.
- كل عملية ذات أثر مالي (فسخ، إلغاء، تغيير…) تنتج إيصالًا/وصلًا، وما لا أثر مالي له لا يُنتج.

## 15. تغيير المركبة

استبدال مركبة البوليصة بمركبة أخرى **للعميل نفسه**. البوليصة **واحدة** (رقمها وتاريخ انتهائها ثابتان) والمتغير هو المركبة فقط. بعد العملية: البوليصة على B، و**A بلا بوليصة** وتبقى مسجلة في ملف العميل. لا نسخة جديدة من البوليصة ولا يُحذف شيء.

**الشروط:**

- مسموح فقط لبوليصة **نشطة زمنيًا** (ليس منتهية أو مفسوخة أو ملغاة).
- تاريخ التنفيذ هو **تاريخ اليوم** دائمًا.
- المركبة الجديدة: جديدة أو مسجلة للعميل، ويُمنع إن كانت لها **بوليصة نشطة** في النظام.
- **رقم شهادة جديد وفريد** (داخل الشركة) إلزامي.
- يُحفظ في سجل البوليصة: المركبة السابقة، رقم الشهادة السابق، المستخدم، التاريخ، السبب.
- يكفي صلاحية تعديل البوليصة. يُنتج **وصلًا A5**.

**الأثر المالي** (الفرق = سعر التأمين الجديد − القديم):

| الحالة | المطلوب |
| --- | --- |
| **زيادة** | الفرق + 17 (مثلًا فرق 300 → يدفع 317) |
| **ثبات** | 17 فقط |
| **نقصان** | يُرتجع للعميل الفرق − 17 (مستحق 120 → يستلم 103) |

- **نافذة التأكيد** قبل الإتمام: رقم البوليصة، المركبة السابقة والجديدة، رقم الشهادة الجديد، الفرق والرسوم والصافي.
- **رسم الـ17 يُحصَّل نقدًا فورًا إن دفعه العميل** (فيدخل الدرج). إن لم يدفعه فورًا يُضاف إلى **أقرب قسط غير مسدد**، وإلا إلى **الدين**، وإلا يُنشأ **دين جديد**. (هذا يلغي شرط «لا حفظ قبل التحصيل».)
- **زيادة الفرق** تُضاف إلى الأقساط أو المبلغ المتبقي (أو تُدفع فورًا).
- **النقصان:** حركة مالية **واحدة** بصافي 103 يفصّل إيصالها المرتجع 120 والرسم 17. إن لم يكف الدرج، يُرفع الطلب للمدير تلقائيًا.
- كل تحصيل أو استرجاع حركة موثقة مرتبطة بالعملية.

**نقصان السعر مع وجود دين أو أقساط غير مسددة:** يُخصم المستحق للعميل (الفرق − 17) من الدين أو الأقساط المتبقية أولًا، وما زاد على المتبقي يُصرف بالقواعد المعتادة.

## 16. تغيير رقم الترقيم

- يخص **المركبة نفسها** فقط، ولبوليصة **نشطة زمنيًا** فقط.
- لا يتغير رقم البوليصة أو تاريخ انتهائها أو مبلغها أو أقساطها الأصلية.
- التنفيذ بتاريخ اليوم. يُحتفظ بالرقم السابق ويُعرض الجديد كالحالي.
- **رقم شهادة جديد وفريد** إلزامي، **ورسم ثابت 17 درهمًا** بنفس قاعدة النقد الفوري/ثم القسط الأقرب/ثم الدين/ثم دين جديد.
- نافذة تأكيد قبل الحفظ. يسجل في الحركات والتدقيق ويرتبط بالعملية. يُنتج **وصلًا A5**. يكفي صلاحية تعديل البوليصة.

### 16.1 نسخة بديلة (Duplicata)

عند ضياع شهادة التأمين أو إتلافها ورقيًا، يستخرج الموظف **نسخة بديلة** للعميل: هي نسخة طبق الأصل من الشهادة السابقة بنفس معلوماتها، تُطبع على شهادة جديدة.

- **رقم شهادة جديد وفريد إلزامي (داخل الشركة)** ولا تتغير معلومات الشهادة إطلاقًا: تبقى كما كانت حرفيًا، ولا يتغير شيء في البوليصة أو المركبة أو التواريخ أو المبلغ أو الأقساط. تُسجَّل كعملية على البوليصة (`duplicate`) باسم المنفذ وتاريخ اليوم والسبب، مع رقم الشهادة السابق والجديد.
- **رسم ثابت 17 درهمًا** بنفس قاعدة رسوم الشهادة: يُحصَّل نقدًا فورًا إن دفعه العميل (ويدخل الدرج)، وإلا يُضاف إلى أقرب قسط غير مسدد، وإلا إلى الدين، وإلا يُنشأ دين جديد.
- نافذة تأكيد قبل الحفظ تعرض البوليصة والمركبة ورقم الشهادة السابق والجديد والرسم. تُسجَّل الحركة والتدقيق، ويُنتج **وصلًا A5** من التسلسل العادي.
- يكفي صلاحية تعديل البوليصة. في الأسطول تُحدَّد المركبة المعنية، ولكل نسخة رسمها.
- يمكن تكرار العملية أكثر من مرة، ويظهر عددها في سجل البوليصة.
- **مؤكَّد:** تُسمح لبوليصة **نشطة زمنيًا** فقط.

## 17. الحسابات والمصاريف والإغلاق

### 17.1 الحسابات

- **الدرج** (واحد فقط): النقد التشغيلي اليومي. **الخزنة:** تخزين الأموال المنقولة من الدرج قبل إيداعها. **البنك:** يستقبل من الخزنة ومن تحصيلات الشيكات والتحويلات والبطاقات المؤكدة.
- **الرصيد الافتتاحي** يحدده المدير **مرة واحدة** عند الإعداد؛ أي تعديل لاحق = «حركة تصحيح» موثقة بسبب.
- **لا رصيد سالب** (قيد في قاعدة البيانات والخادم)، ويمكن للمدير تفعيل السماح للبنك فقط.
- تُحفظ هوية الموظف في كل حركة.
- **المدير وحده ينقل المال** بين الحسابات، وكل نقل يسجل خروجًا ودخولًا في **معاملة واحدة** (`group_id`). حقل «مرجع/ملاحظة» اختياري للإيداع البنكي.
- جدول الحركات المالية **للإلحاق فقط**؛ الأخطاء تُصحَّح بحركة عكسية لا بتعديل.

كل المبالغ النقدية تدخل **الدرج**، ويحوّلها المدير إلى البنك عند الحاجة (ومنها الدفع لشركات التأمين، انظر 17.4).

### 17.2 المصاريف

- التصنيفات الافتراضية: إيجار، ماء، كهرباء، هاتف، نظافة، لوازم، تنقل. **المدير يضيف تصنيفات**.
- **الموظف يضيف مصروفًا فقط** (من الدرج)، فيدخل «ينتظر الاعتماد» **ولا يؤثر في أي رصيد** قبل الاعتماد، ويصل المدير إشعار.
- المدير **يعتمد أو يرفض مع سبب**، ويختار حساب الصرف عند الاعتماد (الدرج افتراضيًا). المرفوض يبقى في السجل بلا أثر مالي.
- **المدير وحده** يعدل المصروف أو يلغيه، ويسجل مصروفًا بتاريخ سابق أثناء الإدخال التاريخي فقط (تُلغى هذه الصلاحية بعد القفل).

### 17.3 جلسات الدرج والإغلاق اليومي

كل موظف له اسم مستخدم ورقم سري خاصان، ويتحمل مسؤولية ما يؤكده.

- **الإغلاق = تسليم:** ينفذه الموظف أو المدير. يدخل الرصيد الفعلي للدرج، ويحسب النظام الرصيد المتوقع والفرق. **السبب إلزامي عند وجود فرق** (مثل سلفة أمر بها المدير). يظهر إشعار للمدير.
- **فتح جلسة الموظف التالي = استلام:** تظهر له نافذة بالرصيد ليؤكده. أي فرق بعد التأكيد **وغير مصرح عنه من الموظف الأول يتحمله المستلم**.
- **عمليات النقد ممنوعة** على أي موظف حتى يؤكد استلام الدرج، مع بقاء بقية النظام متاحة.
- الإغلاق يُسجل بتاريخ وساعة محددين يراجعهما المدير، ويجوز **أكثر من إغلاق في اليوم**.
- **اليوم المالي** = اليوم الميلادي بتوقيت الدار البيضاء، ولا يُشترط إغلاق اليوم السابق للعمل.
- الإغلاق **لقطة محاسبية** لا تمنع العمليات اللاحقة؛ أي عملية بتاريخ يوم مغلق تجعله «يحتاج مراجعة». **المدير وحده** يعيد فتح اليوم بسبب إلزامي أو يُقرّ المراجعة.
- يُعرض تفصيل الحركات حسب الموظف كمعلومة فقط دون محاسبة تلقائية.

المدير أو المشرف يستطيع **إغلاق جلسة موظف نيابةً عنه** بسبب مسجل، حتى لا يتعطل الدرج بغياب أو نسيان.

### 17.4 الدفع لشركات التأمين والسحب من البنك

حركتان مستقلتان للمدير (والمشرف بصلاحية)، ليستا من المصاريف، حتى تبقى الأرصدة حقيقية دون حساب ديون أو أرباح أو تسويات:

- **دفع إلى شركة تأمين:** الشركة (من القائمة)، المبلغ، التاريخ، رقم التحويل أو الشيك (اختياري)، ملاحظة. المصدر البنك افتراضيًا، وللمدير اختيار الدرج أو الخزنة. حركة خروج واحدة، **بلا ربط ببوالص ولا حساب لما على الشركة أو لها**.
- **سحب من البنك:** المبلغ، التاريخ، **سبب إلزامي** من قائمة (سحب أرباح، سحب شخصي، سلفة، تغطية مصروف نقدي، أخرى؛ وللمدير إضافة أسباب)، وتعليل نصي، ومرجع اختياري. حركة خروج من البنك فقط، **بلا حساب أرباح أو نسب**.
- **ضوابط:** يُرفض أي خروج يتجاوز رصيد الحساب. لا يراهما الموظف. لا تعديل ولا إلغاء، والتصحيح بحركة عكسية موثقة. في الإدخال التاريخي تُسجَّلان بتواريخهما القديمة.
- **التقارير:** تقرير مستقل للدفعات والسحوبات حسب الفترة والشركة والسبب، فيبقى تقرير المصاريف نظيفًا.

## 20. النسخ الاحتياطي والاستعادة

- **يوميًا:** `pg_dump` إلى مجلد Google Drive المتزامن على الخادم، في مجلدات شهرية `YYYY-MM`، مع بصمة SHA-256 وفحص قابلية القراءة، **والاحتفاظ ستة أشهر**. بلا Google Drive API.
- **كل جمعة نحو 13:00 (وقت صلاة الظهر، قابل للضبط): نسخة USB إلزامية.** بعد الموعد تظهر على الخادم شاشة تطلب إدخال USB، **ولا يعمل التطبيق على أي جهاز حتى إتمامها**. إن لم يتوفر USB يستطيع **المدير أو المشرف** التخطي **بسبب مسجل** في التدقيق، مع تنبيه عند التشغيل التالي. وإن كان الخادم مطفأً تُنفَّذ عند أول تشغيل بعده.
- **المدير وحده** يستعرض النسخ أو يستعيدها أو يحذف ملفاتها (يُسجَّل في التدقيق).
- **الاستعادة:** تأكيد صريح، إيقاف الخدمة، **نسخة أمان تلقائية للوضع الحالي**، الاستعادة، فحص التوافق، إعادة التشغيل، تسجيل في التدقيق. اختبر الاستعادة فعليًا في الاختبارات.

### 20.1 النسخ كل ساعة وخطة الطوارئ

- **نسخة كل ساعة** أثناء الدوام إلى Google Drive، تُنظَّف تدريجيًا، إضافة إلى اليومية. أقصى خسارة محتملة ساعة واحدة.
- **«استعادة كخادم»:** وضع في المثبّت يحوّل أي جهاز إلى خادم من آخر نسخة، فتعمل الوكالة خلال نحو ساعة. يُسلَّم **دليل طوارئ من صفحة واحدة** بخطواته.
- **عند عطل الخادم:** وصولات ورقية مرقمة مسبقًا تُدخل لاحقًا، مع حقل اختياري **«رقم الوصل الورقي»** في العملية.
- لا UPS (قرار صاحب المشروع): قاعدة البيانات تتحمل انقطاع الكهرباء دون ضياع العمليات المؤكدة، ويُوثَّق في دليل التشغيل الإطفاء الصحيح للخادم.

## 22. وضع الإدخال التاريخي (المرحلة 7)

الهدف: إدخال **كل** بيانات الوكالة منذ **01/05/2026** إلى النظام بدقة مالية كاملة، **يدويًا**، بواسطة **المدير وحده**. لا استيراد من Excel، ولا مسار «تجديد بوليصة غير مسجلة».

**الوضع والزر:**

- زر يفتح «وضع الإدخال التاريخي»، وشريط أصفر دائم في الواجهة طوال بقائه. الصلاحية للمدير وحده.
- كل عملية تُدخل **بتاريخها الأصلي** وتُنشئ **حركاتها المالية بذلك التاريخ** وإيصالها كاملًا من أول عملية (بتسلسل الإيصالات العادي)، وتُنسب لاسم المدير. يسجل التدقيق وقت الإدخال الفعلي إلى جانب تاريخ العملية.
- كل المبالغ النقدية تدخل **الدرج**، ثم يحوّلها المدير إلى البنك (ومنها تصفية الشركات عبر حركة «دفع إلى شركة تأمين» (17.4)). الرصيد الافتتاحي في 01/05/2026 يحدده المدير (غالبًا صفر).
- قواعد الزمن (التجديد E وE+1، فسخ الـ15 يومًا، وجود تأمين ساري على مركبة) تُحسب **بتاريخ العملية لا بتاريخ اليوم**، ويلزم الإدخال بترتيب زمني من الأقدم إلى الأحدث داخل البوليصة الواحدة.
- قاعدة «لا رصيد سالب» **معلَّقة أثناء الإدخال** ويُفحص كل يوم عند الإنهاء.
- لا تحول تلقائي للدين على الماضي: تُدخل الحالة الفعلية للقسط. للمدير تعديل الأقساط والرسوم يدويًا بقيمها القديمة مع وسم كل تعديل.
- الدفعات الجزئية بتواريخ ومبالغ متعددة عبر «تفاصيل الدفعات». الشيك القديم المقبوض يُسجَّل «مؤكدًا» بتاريخ تأكيده.
- لا إغلاقات يومية ولا جلسات درج تاريخية؛ الأرصدة تكفي.
- التقارير تميّز هذه السجلات بعلامة «تاريخي» وفلتر مستقل.

**شاشة الإدخال السريع:** نماذج حفظ-والتالي بـ`Ctrl+Enter`، تذكر آخر شركة ونوع تأمين، بحث العميل بالهوية مع إكمال تلقائي، حساب فوري لجدول الأقساط والرسوم، وتنبيه فوري للشهادة المكررة أو الرصيد السالب.

**زر «تمت كل الادخالات القديمة»:**

1. قائمة فحص: أرصدة الدرج والخزنة والبنك للمقارنة بالواقع (حركة تصحيح بسبب عند الاختلاف)، أي يوم رصيده سالب، الأقساط المتأخرة، الشيكات غير المحسومة، البوالص المنتهية.
2. نسخة احتياطية تلقائية قبل التنفيذ.
3. تأكيد بكلمة مرور المدير وكتابة عبارة محددة.
4. **قفل نهائي** داخل التطبيق: لا إدخال بتاريخ سابق بعده، وتُلغى صلاحية «مصروف بتاريخ سابق». يُحسب وضع اليوم مرة واحدة مع **رسالة ملخصة واحدة** للمدير، وتبدأ القواعد الحية.
5. التصحيح لاحقًا بحركة تصحيح بتاريخ اليوم وسبب موثق. وتظهر للمدير نافذة تذكّره بخطوات التصحيح (أو استعادة نسخة سابقة) عند الحاجة.

- **حالات إلزامية للاختبار:** الأقساط ورسوم 17 والأمثلة في 14.4 (وفروق السنتيم)؛ التحصيل والعكس عند الرفض والارتجاع بعد التأكيد؛ التحول التلقائي للدين (D+3) واستدراك المهمة الفائتة؛ تجديد E وE+1 وE+2 وحالة تغير التوقيت؛ الفسخ (مدفوعة 15 يومًا، مقسّطة في أي وقت، سقوط الدين) والإلغاء (منع المقسّطة، خصم الدين المباشر)؛ تغيير المركبة (زيادة وثبات ونقصان وأمثلة 317 و17 و103، ورفض مركبة بتأمين ساري، وشهادة مكررة)؛ تغيير الترقيم؛ رسوم 17 النقدية أو الإضافة للقسط/الدين؛ الأرصدة والتحويلات ومنع الرصيد السالب؛ **التزامن** (دفعتان متزامنتان، مفتاح عدم التكرار، حالات تشابك)؛ المصاريف قيد الاعتماد؛ الإغلاق والفروقات وتسليم الدرج ومنع النقد قبل التأكيد؛ الصلاحيات (واختبار المسارات بلا تصريح، وإخفاء الخزنة والبنك عن الموظف)؛ سجل التدقيق للإلحاق فقط؛ الاستعادة من نسخة احتياطية.
- لا يُسلَّم أي منطق مالي بلا اختبارات ناجحة.

**اختبارات إضافية:** صيغ الترقيم الأربع وفرادتها بعد التطبيع؛ الوضع التاريخي (ترتيب زمني، تواريخ مرجعية، عدم سلبية الرصيد في أي يوم، القفل والتصحيح)؛ النسخة كل ساعة والاستعادة كخادم؛ إغلاق جلسة نيابةً؛ خصم النقصان من الدين؛ الدفع للشركات والسحب من البنك (رفض الرصيد السالب، السبب الإلزامي، إخفاؤهما عن الموظف)؛ سلامة اللغتين (لا نص ثابتًا، ومقابل لكل مفتاح ترجمة).

## 25. مخطط قاعدة البيانات المعتمد (ملخص)

**اصطلاحات:** UUID للمعرفات. المبالغ `bigint` بالسنتيم، MAD فقط. الجداول الرئيسية: `created_at/by`, `updated_at`, `version`, `archived_at`. يُعرض المخطط التفصيلي كاملًا (حقول وقيود وفهارس) في بداية المرحلة 1 للموافقة النهائية.

- **المستخدمون والتدقيق:** `users` (مدير واحد بفهرس جزئي فريد، `is_supervisor`، `failed_attempts`, `locked_until`)، `user_permissions`، `sessions`، `audit_log` (إلحاق فقط)، `notifications`، `message_threads`، `messages`، `message_recipients` (to/cc)، `edit_requests`، `sequences`.
- **الإعدادات:** `agency_settings` (صف واحد: بيانات الوكالة والشعار والمهل ورسم 1700 سنتيم)، `insurers`، `insurance_types`، `coverage_durations`، `expense_categories`، `operation_types`، `whatsapp_templates`.
- **العملاء والمركبات:** `clients` (فريد: نوع الهوية + الرقم)، `vehicles`، `vehicle_plate_history`، `fleets`، `fleet_vehicles`.
- **البوالص:** `policies` (فريد: شركة + رقم)، `policy_periods` (`validity_status` و`collection_status` مستقلان، CHECK للتواريخ)، `certificates` (فريد: شركة + رقم)، `period_vehicles`، `policy_operations`.
- **الأداءات:** `installment_plans`، `installments` (pending/partial/paid/converted\_to\_debt)، `debts` (المصدر والمتبقي)، `payments` (مفتاح عدم التكرار)، `payment_allocations` (قسط أو دين، أحدهما فقط)، `cheque_details`، `transfer_details`، `receipts` (رقم فريد، لقطة JSON).
- **المال:** `accounts` (CHECK رصيد ≥ 0، درج واحد)، `financial_transactions` (إلحاق فقط، `group_id`, `reverses_transaction_id`)، `transfers`، `expenses`، `drawer_sessions`.
- **المتابعة والتشغيل:** `claims`، `contact_logs`، `backup_runs`، `usb_backup_gates`، `job_runs` (فريد: مهمة + تاريخ)، `import_batches`، `import_rows`، `system_info`.
- **فهارس مهمة:** بحث العملاء (`pg_trgm`)، (نهاية البوليصة + حالة السريان)، (حالة القسط + مهلته)، (حساب + وقت الحركة)، (نوع الكيان + معرفه) في التدقيق.

**إضافات معتمدة:** `vehicles.plate_type` (`ma`/`ww`/`foreign`/`state`) مع `plate_normalized` فريد؛ `is_historical` و`entered_at` على العمليات والحركات والإيصالات؛ `paper_receipt_no` اختياري؛ `system_info.historical_mode` (`open`/`locked`) و`go_live_at`؛ جدولا \`insurer\_payments\` و\`bank\_withdrawals\` (مع \`withdrawal\_reasons\`) للإلحاق فقط؛ `drawer_sessions.closed_on_behalf_by`؛ `backup_runs.kind` يضم `hourly`.

## 27. افتراضات مسجّلة تحتاج تأكيدًا عند بلوغ مرحلتها

لم تُحسم صراحةً، فلا تنفذها قبل سؤال صاحب المشروع (أو اعتمد الافتراض المكتوب إن وافق):

1. **الفسخ لبوليصة عليها دين مباشر:** افتراض: خلال 15 يومًا، ويُسترجع ما دُفع فعلًا فقط ويسقط الدين.
2. **تجديد بدأ بعد E:** تاريخ البداية الافتراضي هو E (انتهاء القديمة)، مع إمكانية إدخال غيره للمدير.
3. **تصحيح الرصيد الافتتاحي:** يُسجَّل كحركة تصحيح لا كتعديل.
4. **عدد الأجهزة:** 3 حاليًا، والتصميم يدعم أكثر دون تعديل.
5. **نقصان السعر مع دين (تغيير المركبة):** حُسم بأن يُخصم من الدين (انظر 15)؛ والمفترض أن ما زاد على الدين يُصرف نقدًا.
